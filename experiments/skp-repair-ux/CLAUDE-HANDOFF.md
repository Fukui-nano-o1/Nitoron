# Claude Code 引き渡し：修理 UI

2026-09-13。目的は「利用者が機械・部品・案内・結果へ迷わず進めること」。下記Q1〜Q7を固定し、実操作は `BROWSER-CHECK.md` のU1〜U9と環境差分で確認してください。

| 固定条件 | 合格の要点 | 実操作 |
|---|---|---|
| Q1 発表と修理を分ける | 修理が発表フォームを経由しない。通常発表・既存修理URLを維持する。 | U1 |
| Q2 説明を収納する | 主画面は短い操作表示。初回案内を閉じて進め、必要時に再表示できる。原典・作業条件へ到達でき、必要条件の未確認を実施済みにしない。 | U2・U3 |
| Q3 3Dの復元 | 保存・再読込・公開詳細で機種・版・部品を復元。案内や部品選択を閉じても回答を保持して3Dを再表示する。未知機種・版をSKPで代用せず、未知部品の元参照を保つ。 | U4・U5・U9 |
| Q4 分解の動き | 全体→中間→部品を実際の描画で確認する。操作で動きが止まり、動きを減らす設定では途中演出を省く。保存対象は書き換えない。 | U4・環境差分 |
| Q5 結果を残す | 保存失敗は未保存のまま入力を保持。訂正・再送後は最終案だけを一度追記し、既存内容と出典を壊さない。 | U6・U7 |
| Q6 既存記録を維持 | 過去の観測・条件・補足と公開管理に到達できる。公開詳細は公開スナップショットだけを使い、私有下書きを混ぜない。 | U8 |
| Q7 利用環境 | 390px／1280pxで主要操作を読める。WebGLなしでも案内と結果保存が使える。実機iPhoneを使わない場合は未確認を維持する。 | 環境差分 |

**現在の証拠**：関連Node64/64、サーバー描画6/6、ビルド成功。ブラウザ・実機iPhone・実修理は未確認。SSRは画面構造の検査で、描画・操作・読みやすさの証明ではありません。

**他メーカー**：架空の2メーカーで共通データ契約の解決・保存往復を検査済み。実登録はSKP-101Wの1機種のみ。他メーカーの3D生成、手順適合、寸法精度は未検証です。3D移動は閲覧演出であり実際の分解手順ではありません。

報告は「利用者がどこまで進めたか」「Q1〜Q7合否」「実現性・再現性・課題・次の仮説1件」。不具合には再現手順と最小差分を添付し、変更部分に必要な検査だけを追加してください。実物99%一致・修理成功・新メーカー対応を、今回のUI検査から認定しないでください。

参考にした公開設計：Airbnbの[目的別入口と詳細・Tripsの構成（2025-05-13）](https://news.airbnb.com/airbnb-2025-summer-release)、[2026年の詳細・選択の構成（2026-05-20）](https://news.airbnb.com/airbnb-2026-summer-release)。説明ボタン、初回案内、機械の分解表示は利用者の要望に合わせたNitoron側の設計です。
