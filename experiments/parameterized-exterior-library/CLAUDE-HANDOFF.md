最新origin/mainと作業ツリーを確認。前回報告は `1ab3105`。Codexは今回リモートを取得していないため、これを現在の最新値と断定せず、新しい変更を保持する。

ZIPを `experiments/parameterized-exterior-library/` に追加し、部品庫・寸法ボックス・部品交換の既存フォルダは上書きしない。本候補内で接続を検証する。`SHA256.json`を照合。`review.patch`は手元の前回候補との差分閲覧用で、現在mainに無条件適用しない。基点の出所は `baseline/previous-source-identities.json`。

## 実行と判定

実験内で `npm test` → `npm run build` → `npm run check:browser`。必要時のみ `ATLAS_CHROMIUM_PATH` を実在Chromiumへ指定。Three r180/MIT同梱、有料API不要。本番通信なし。

ファイル入力は `file.text()` 完了後の表示を待って判定する。カメラの許容差1e-8mmと、形状配列・失敗時データの厳密比較を区別する。閾値変更・検証対象の縮小はしない。

E1〜E7、実行環境とSHA、件数、変更ファイル、修正diffを一括報告。再現した問題のみ最小修正。合格後はこの工程を閉じる。通常mainプッシュは既存許可内で検証後に実施。強制プッシュ・本番DB・課金・公開デプロイは行わない。

今回共通化したのは生成1種類、既存3曲面への適用を単体検証、画面接続は1部品。人手工数削減率・新機種の実寸再現・型番だけの自動生成の達成には数えない。最終利用者の入口はメーカー名・型番のまま。寸法入力は開発側の整備用。
