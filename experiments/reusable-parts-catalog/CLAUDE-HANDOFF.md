# Claude Codeへ：部品を一度作り、分類・保存して流用する

2026-09-11 / Codexコード同梱。前回の「部品形状を交換できる寸法ボックス」は維持し、その上位に置く共通部品庫を検証する。

## 今回の判断

ボルト・ワイヤー・凹凸は3D化できる。毎機種で作り直さず、寸法付きの部品レシピと図面参照を保存する。ただし見た目だけで同一部品や互換性を断定しない。実際の機械に使われるねじ径・ピッチ・強度・配線経路など、資料で判別できない情報は確認できませんと記録する。

## 分類（初期実装と拡張枠を混同しない）

| 大分類 | 保存する部品群 | 今回コード |
|---|---|---|
| 締結 | ボルト、ナット、座金、ピン、止め輪、クリップ | ボルト・ナット・座金 |
| 回転・伝達 | 軸、軸受、歯車、プーリ、ベルト、チェーン | 分類案のみ |
| 配線・配管 | 電線、操作ワイヤー、ホース、コネクタ、継手 | ケーブル断面＋配置経路 |
| 外装・支持 | カバー、パネル、リブ、ブラケット、フレーム | リブ付きパネル |
| 操作・原動機・足回り | レバー、スイッチ、エンジン構成部、タイヤ、クローラ | 分類案のみ |

ボルトは直径・首下長さ・頭形状・二面幅・ピッチを分ける。外観が同じでも規格や材質の同一視は禁止。ケーブルは断面と端末、取付経路を分ける。今回は断面と経路のみで、端末や内部導体は未実装。形状の凹凸はリブ・穴・ねじ山のような形を生成し、塗装肌などの見た目だけの凹凸は今後別レイヤーにする。今回ノーマルマップは使わない。

## コードの対象

ZIPを `experiments/reusable-parts-catalog/` 等の独立ディレクトリへ配置。既存ファイルを上書きしない。最新mainを確認し、前回の部品交換が既に取り込まれていても戻さない。今回の追加コードはNitoron本体・DB・実ジョブ原本・PC752N形状・旧実験へ未接続。前回成果物の一括差替えは不要。

- catalog.mjs：版を固定した部品レシピ、JSON保存・読込、同一版の改変拒否。
- geometry.mjs：形状生成・共有キャッシュ・配置個体。材質と選択は個体別。詳細と全体表示の形状を分ける。
- drawing.mjs：同じレシピからSVG模式図。製造用図面と呼ばない。
- app.mjs：同じ部品を仮想配置先A/Bへ表示。寸法違いの保存、別ブラウザへのJSON受け渡しを検証する開発用UI。

## 固定達成条件 R1〜R7

| 条件 | 必要な結果 |
|---|---|
| R1 分類と版 | 5分類の生成に成功。部品キー・版・寸法・出所を保持。同じ版の寸法上書きを拒否。 |
| R2 形状再利用 | 同寸法・同LODのボルトを100個配置し、形状生成1回。同一geometry参照、個体ID・位置・色は別。FPS改善は測っていないため主張しない。 |
| R3 細部 | 詳細表示に実形状のねじ山・穴・リブ。全体用ボルトでねじ山を省略。標準規格に完全一致したとは報告しない。 |
| R4 経路 | 同じケーブル断面でも異なる取付経路は別形状。別機種の経路・適合を流用しない。 |
| R5 保存 | 30mmと40mmのボルトを別部品として保存・再読込。JSONを未保存のブラウザへ読み込み再利用。保存失敗は明示。 |
| R6 出所と安全な復元 | 不正入力・版衝突で既存カタログ不変。図面参照と模式図を保存。新しい機種配置はunconfirmed、資料照合済み3D=0。 |
| R7 検証と範囲 | npm test・build・check:browser。390px/1280px、エラー0、外部通信0、生成再現性。本体取り込み後のnpm test/build。実機iPhoneは未確認なら未確認。 |

再現した不具合は最小修正して差分を示す。全基準の結果・実行SHA・件数・課題を一括報告。通常mainプッシュは既存の許可内で検証後に行い、force push・本番DB・課金・デプロイ・追加の研究ループは行わない。

## 重要な境界

実商品への自動採用、既存の交換用JSONへの自動変換、機種部品IDとの紐付けは未接続。一つのボルトが複数メッシュを持つため、既存の単一メッシュ形式へ渡すなら、座標系・全メッシュ・寸法の照合を伴う別の接続が必要。部品庫の成立を実機再現や互換部品判定の成立に読み替えない。既存の174描画要素を今回の推定ボルトへ一括置換しない。

利用者の操作は最終的にメーカー・型番の入力のまま。寸法入力、図面収集、部品の分類と検証は開発側の整備作業。この試作の入力UIをそのまま一般利用者へ要求しない。
