# Claude Code 指示書：形状を交換できる寸法ボックス

## 今回の目的

Cadasioの公開仕様にある「組立構造・部品の形状・表示手順を分け、モデル更新後も説明を維持する」設計を、独立したコードで取り入れました。添付コードを実行・検証し、再現した不具合のみ最小修正して、一括報告してください。新しい設計案だけを返して停止する必要はありません。

## 基点と取り込み

基点は `c7faa3bbaa4338fd6ee9305bc637b9d0c44e8e5b`。mainにある `experiments/pc752n-dimension-boxes/` のソース・モデル・vendorとCodex手元の原本はGit blobで一致確認済み。証拠画像等7ファイルはClaude再実行で相違しているため、原本一致の対象から区別しました。記録はBASELINE.json。

1. 最新origin/main、祖先関係、作業ツリーを確認。以後の変更を保持。古いSHAへリセットしない。
2. ZIP内 `review.patch` の対象は上記experimentディレクトリのみ（ソースと検証契約）。生成HTMLは適用後のbuildで更新する。まず `git apply --check` で確認し、適用する。ZIPの `pc752n-updatable-parts/` は完全な候補ソース兼比較用。パッチと全コピーの二重適用はしない。新しい同時変更があれば差分を統合する。
3. `src/model.mjs`、vendor、sources.json、docsの実測設計、既存の実ジョブ原本、v1〜v4実験を改変しない。本体共有ホストや2D25点への接続、型式検索、追加機種・写真取得、課金、DB適用、デプロイは今回対象外。
4. コードの通常mainプッシュは利用者の既存許可の範囲で、最新変更を保持し検証後に実施。強制プッシュしない。Codex側では今回リモート操作・コミット・プッシュを行っていない。

## 実装の読み方

- original model: 6グループ・174メッシュを維持。174は描画部品数で、実機の全部品数ではない。
- assembly: 固定部品ID／元の組立変換／形状の版／表示用分解移動量を保持。形状を入れ替えてもIDを生成し直さない。
- presentation: 全体・構成・外装・ケーブル・エンジンの表示ガイド。修理手順や実際の取り外し順を主張しない。
- part-package: 一部品のローカルJSON。部品ID・機種仕様・mm座標系・旧版一致・有限座標・面・サイズ・根拠を検査。親子、位置、材質などの差し替えは許さない。
- app: 同一の論理部品のgeometryだけ交換し、全体と部品の二箱へ反映。現在の選択・視点・分解途中・透過・表示ガイドを維持。視点座標の検査のみ浮動小数演算の丸め誤差1e-8mmを許容し、他の状態は厳密一致。選択部品の直前1版へ戻せる。

JSONの読み込み欄は「検証用」の折り畳み欄。利用者にこの操作を要求する製品仕様ではない。保存先はページ内メモリのみで、閉じると消えることを画面に明示。必要な形状はJSONに書き出すと、再読込した初期モデルへ読み戻せる。CAD/STEP/GLB直接読込やNitoron内の永続保存は未実装。

## 固定達成条件 C1〜C7

| 条件 | 合否の観測 |
|---|---|
| C1 原本と識別 | 元モデル・vendor不変。6グループ174IDが一意。旧element IDで同じ部品へ解決。交換後も親子・組立位置・ID不変。 |
| C2 実際の形状交換 | cowling-revision.jsonをファイル入力で読み、両箱の実頂点が126→246へ変わる。形状版・出所が更新される。ラベル変更だけでは不可。 |
| C3 操作維持 | 選択、両カメラ、分解移動量、透過、ガイドが交換前後で一致。分解途中に交換しても継続し、完了・組立へ戻る。既存のタップ・ダブルタップ・ボタンも維持。 |
| C4 失敗と復元 | 機種違い、旧版違い、不正座標、面、未知ID、全体外寸変更、110mm幅の違反で交換しない。元形状とundo状態不変。直前1版へ戻すと形状・出所・版が一致。 |
| C5 精度の扱い | 申告がmeasured/CADでもpending-review。documented3dParts=0。全体外寸の0.01mmは計算チェックで実機精度保証ではない。形状fixtureは同じ仮定曲面の分割数変更だけ。 |
| C6 実行と再現 | npm test、build、既存14操作＋追加交換操作。390px/1280px・外部実行通信0・ページエラー0。生成HTMLは2回同一。出力メタデータは3回一致。iPhone実機は未確認と区別。 |
| C7 取り込み回帰 | 実験ディレクトリ外の本体コード不変。本体のnpm testとbuildを確認。改変していない過去実験の再実行を増やさない。結果・差分・未確認を一括報告。 |

## 実行

実験ディレクトリで `npm test` → `npm run build` → `npm run check:browser`。Playwright/Chromiumが環境にある場合はそれを使用し、必要ならATLAS_CHROMIUM_PATHを指定。実行環境パスの変更とアプリ不具合を分ける。閾値や観測項目を緩めて合格にしない。

C1〜C6は同梱 evidence にCodex実行結果あり。browser証拠画像は比較用とし、パッチでは既存証拠を上書きしない。SHA256.jsonは候補ソースと生成HTMLの検証用。C7の最新Nitoron全体回帰はClaudeが取り込み後に実施。今回の形状は前回試作から変えていないので、B6外観の改善や全部品実寸の合格に格上げしない。

## 報告形式

C1〜C7の合否、実行SHA、変更ファイルと修正diff、ブラウザ・OS、実数のテスト件数、何が保持され何が未確認かを一括で報告。新しい研究ループや追加機能へは進まず、ここでこの変更を閉じる。
