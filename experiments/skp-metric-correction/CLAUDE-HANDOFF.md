# SKP-101W：寸法を歪める拡縮の撤去・車輪径修正候補

2026-09-12 / Codex → Claude Code / 固定条件 M1〜M8

## 結論と今回の範囲

Codexが候補コードを作成済み。Claudeは実行し、実現性・再現性・課題・次の仮説を一括報告する。
対象は SKP-101W。優先順位②「原寸カタログの再現性」に向けて、実寸を歪める土台を先に修正する。
工程Aや世界中の機械の99%再現が達成したとは判定しない。

基点：GitHub main `76fd603ec1156f8ff9b2a670d7bb6cda0de1a927` を読み取り確認。
原本生成コード4ファイルとThree関連4ファイルはGit blobまで一致。現在のmainが進んでいれば新規変更を保持し、この原本との違いを先に報告する。reset/forceは禁止。

取り込み先：`experiments/skp-metric-correction/` の独立候補。既存のvendorモデル、カタログ、公開snapshot、DBは変更しない。
`review-only.patch` は候補との差分閲覧用。本体へ `git apply` する指示ではない。
ユーザーのmain通常プッシュ許可は継続しているが、このコードは検証後も独立実験として保存する範囲。既存モデル版を差し替えたり本番3Dに接続したりしない。

## 1. 今回変えたこと

- `src/skp-geometry.js`：包絡寸法からのX/Y/Z拡縮を廃止。元のメートル単位と固定原点を保持。全体寸法は参照値と実測値に分離。旧モデルの包絡に合わせた再中心化も行わない。
- `src/skp-model.js` / `wheel-spec.mjs`：車輪の生成半径だけを変更。軸中心・幅・車軸・他29群の配置は変更しない。
- `scripts/calibrate.mjs`：公式公称径を、ラグを含むタイヤの外接径に対応させる生成パラメータを二分探索。メッシュの事後拡縮ではない。前輪r=0.181762585m、後輪r=0.2106708497m。
- 比較は旧モデル／拡縮だけ撤去／車輪径も修正の3段階。旧モデル→候補の変化と、車輪修正だけの変化を混同しない。

車輪の `r` はスプライン形状の制御値であり、ラグ込み外径/2ではない。Claudeの4行パッチは旧変形の補償であるため、この候補へ重ねない。

## 2. 寸法・真円性の定義（実行前に固定）

- 単位：コードm、報告mm。X=機体長手、Y=鉛直、Z=機体幅。左右符号の実機対応は追加確認事項。
- 車輪径：車軸（各車輪群の原点）からタイヤ全頂点へのXY距離の最大値×2。ラグを含む外接径。
- 公式公称径：前368mm／後457mm。資料は取説物理108頁・印刷90頁。公称径をこの幾何定義へ対応させるのは今回のモデリング規約。荷重変形・空気圧・測定姿勢まで資料で確定したわけではない。
- 径のソフトウェア許容差：±0.05mm。実物の製造公差・修理適合公差ではない。
- 真円性：ラグを除く回転体の、同じ軸方向断面で半径最大−最小が0.001mm未満。タイヤとリムを4輪すべて検査。
- 測定器は現生成順・Z車軸を前提とする専用品。別形状・別軸へ無検証で流用しない。
- 後輪ラグは14分割であるため、AABB上下幅=外接径を要求しない。候補の上下幅449.13mm／外接径457mmを別々に表示する。
- 全体外寸：組立メッシュ全頂点の包絡。名目値へ合わせ込まず差を報告。
- 接地：タイヤ実メッシュの最低Y。`y-r`で代用しない。y=0は旧コードの固定基準面であり、実機の地面の実測根拠はない。

## 4. エンジンについての報告訂正

エンジン群をGB131標準寸法へ縮小する指示は出さない。SKPのGB131LN-231は取説で燃料4.8L、Willbe標準GB131は2.5L。資料に仕様差がある。
標準系列の公称297×354.5×330.5mmは確認できるが、-231の包絡や機体軸への対応は未確認。
C07のねじ注記は7-M8×1.25・ねじ深15。C06の取付穴（長穴2＋φ9穴2）と混同しない。詳細は `ENGINE-EVIDENCE.md` / `sources.json`。

## 5. 実行手順

1. `SHA256.json` を `node scripts/verify-package.mjs` で照合。`baseline/source-identities.json` と main の対象4ファイルも照合する。
2. `npm test`。元モデル、円筒/斜め棒、全輪の径/真円、29群不変、全33群/214詳細ID、分解復帰、残差と非認定を確認。
3. `npm run measure`。同梱 `evidence/measurements.json` と同条件で一致するか確認。異なるなら先に差の箇所・Node/Three版を報告する。合格用の数値変更は禁止。
4. `npm run build`。単一HTMLと再ビルドのSHAを比較。
5. `npm run check:browser`。環境にPlaywright/Chromiumがなければ通常の検証環境を用意。`ATLAS_CHROMIUM_PATH` を指定可。390pxタッチと1280px、3段階、対象選択、回転/ズーム、分解復帰、透過、WebGL不成立時の数表を検査。スクリプト検査だけでなく赤円と各輪の表示を目視。
6. 同じカメラの比較画像、ブラウザ検証JSON、修正diff（あれば）、一括報告を提出。実機iPhoneは未確認と明記。既存本体は変更しないため全回帰の機械的な繰り返しは不要。共有コードを変更する必要が生じた場合のみ、対象の回帰を追加。

`SKP-101W-metric-viewer.html` は依存を同梱した表示用。`model.mjs`単体をユーザーに開かせない。iPhoneの添付プレビューでHTMLを実行できるかは別事項であり、確認せず「Safariで必ず動く」と報告しない。

## 7. 報告の形式と次の一件

結論は「単位/車輪修正を採用できるか」と「実機モデルが完成したか」を別に書く。
実現性＝動いた操作・成立した計測。再現性＝SHA/数値/環境。課題＝接地/接続/全体寸法の残差と資料不足。仮説＝次に一度で確かめる変更を1件。

次に必要なのは、タイヤを見かけだけ接地させることではなく、**前後車軸の接続点と調整姿勢を資料に結び付けて定義すること**。
今回のレビューで既存コードの軸/支持部の候補アンカーと資料の対応箇所を表にする（未確定は未確定）。資料のない絶対座標を捏造せず、ハンドル部品庫や別機種実験へ逸れない。
寸法・位置・形状・部品同定の評価対象と未測定の分母が未確定なため、全体99%の判定はまだできない。今回のソフトウェア許容差を99%達成へ読み替えない。
