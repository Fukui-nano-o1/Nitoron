# Nitoron / 4Hクラブの経営発表 — 第1段階

更新日：2026-09-07

## この変更でつながる流れ

1. 自分の記録に、経営発表・挑戦・学習ノート・メモを作る。
2. 課題、仮説、実践、結果、考察、学びを分け、観測した事実に日付・条件・根拠を添える。
3. 下書きを保存する。既存のメモとブロックも引き継ぐ。
4. 確認画面で公開対象を読んでから公開する。公開版の更新は明示操作とし、下書きの編集で自動更新しない。
5. 公開リンクで閲覧・共有。質問・指摘・提案・試した結果を投稿する。
6. 他の発表を参照して学習ノートや挑戦を作る。元の実績数値は自分の実績としてコピーしない。
7. 最大3件を並べ、作物・品種・地域・面積・期間・条件と、数字・仮説・結果を比較する。

学習や挑戦からも次の記録を作れます。関連元は出典として残ります。未入力数値は0として扱いません。10a換算には対象面積が必要です。数字の差は因果関係を意味しません。

## 保存と互換性

- React/Vite/Supabaseと既存notes・settingsを継続利用。ライブラリの既存解決済みバージョンを固定。
- 発表の構造化情報はnotes.blocksの専用メタデータブロックに保存する。既存メモを破棄しない。
- 端末内の旧データとクラウドが異なる場合は、端末側を復元用の別記録として保管する。
- 未送信の編集を端末に保管し、保存は順番に送信する。通信失敗で未送信内容を消さない。
- クラウドへの応答を確認してから「保存済み」「公開しました」を表示する。
- 全記録をJSONで書き出し・取り込み、個別記録をMarkdownで書き出せる。読む画面から印刷・PDF保存も可能。
- 端末の仮アカウントはメール確認を経て恒久アカウントに移行する。既存アカウントへのログイン時に、仮アカウントの記録を勝手に移さない。

## 権限設計

- 公開の読み取り：is_public=trueのスナップショットのみ。未公開版と指摘は所有者のみ。
- 公開・更新：元のnotesの所有者かつメール確認済みユーザー。
- 指摘の投稿：メール確認済み本人のみ。対象発表は公開中であること。
- 指摘の削除：投稿者または発表者。
- 公開停止：公開一覧・共有リンク・他者向けの指摘表示から外れる。所有者は読む画面から過去の指摘を確認できる。
- 投稿は40件/24時間・10秒以上の間隔。削除で回数制限をリセットできない内部カウンタを使用。
- privateスキーマ内の認証確認とレート制限だけに限定したSECURITY DEFINERを使用。呼び出し元のauth.uid()を検査し、公開RPCにはしない。
