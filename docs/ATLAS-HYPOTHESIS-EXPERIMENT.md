# Codex実装案をClaude Codeで検証する

作成日: 2026-09-11。確認基点: `14e7637be76e1a58368dfe996429f198734db4c0`。
これは実験用の追加パッチです。既存の `run.mjs`、`assemble.mjs`、公開画面、DB、工程Aの合格判定を変更しません。

## 分担と、今回答えること

Codexがコード案とテストを書く。Claude Codeが実データで実行し、実現性・再現性・課題・仮説を報告する。利用者はPDFとZIPをClaudeへ渡すだけでよく、PC操作や座標入力を担当しない。

現行コードは図の25点を取得しても、3Dの配置には寸法比率を使っている。本案は、その切れ目に実験用の計算を入れる。以前のSKP-101Wは形状をコードで定義して描画した実績であり、「型式だけで未登録機種の正しい形状を復元できた」実績ではない。本案もその成功をまだ主張しない。

今回の仮説: **歩行型耕うん機の共通構造を初期仮定にし、資料の引出線の点を使って位置を調整すると、固定配置より検討に使える3D候補を自動生成できるのではないか。** 部品のCAD形状、正しい奥行き、取付位置を資料から確定する処理ではない。

## コードの内容

| ファイル | 処理 |
| --- | --- |
| `scripts/atlas/experimental/reconstruct.mjs` | 部品名の厳密な対応、カテゴリ共通の形状仮定、図のグループ仮定、カメラ探索、位置の調整、奥行き別候補、独立に1点を外す誤差評価 |
| `scripts/atlas/experimental/viewer.mjs` | 現在の生成結果／初期仮定／調整後／近側／遠側を比較。資料の点と再投影を重ねる。既存のThreeを同梱 |
| `scripts/atlas/experimental/run.mjs` | 既存ジョブのmachine.jsonと図を読み、別フォルダに結果を出す。元ファイルは変更しない |
| `scripts/atlas/experimental/check-browser.cjs` | Playwrightで390px・1280px、候補切替、選択、3D失敗時の2D操作を確認するための実行スクリプト |
| `tests/atlas-hypothesis.test.js` と `tests/helpers/atlas-hypothesis-fixture.mjs` | 合成データによる17テスト。PC752N等の実データとは別集計 |

寸法は既存抽出値を使う。実験中の入力は既存のジョブディレクトリだけで、利用者に寸法や写真を求めない。機種名を条件分岐に使わず、共通の部品名規則で処理する。新規依存、有料API、GPUは不要。ブラウザ確認だけはPlaywrightとChromiumの既存実行環境が必要。

### 数学モデルと限界を固定する

- 投影は正射影を仮定する。カメラ方向は24方位×4仰角を探索する。実資料が透視図や変形された説明図なら、この仮定は成立しない可能性がある。
- 初期形状・位置・大きさは、コードに明示したカテゴリ共通の仮定である。機種固有の実測値やCADではない。これを隠して「機械を再現」と呼ばない。
- 図の引出線は部品の表面を指す可能性があるが、計算上は概略形状の中心として扱う。この仮定のずれもClaudeの検証対象。
- 部品中心を図へ投影した誤差と初期位置からの変位を抑える。調整の重みは固定0.5。外形寸法の枠内に収めるが、部品間の衝突・取付関係は解いていない。
- 図の分割は点の空間的な隙間による仮定で、実画像を認識した分割ではない。分割しない対照結果も保存する。同一ページの複数斜視図や差込図の混同を必ず点検する。
- 使うのは既存データで `leader-endpoint` とされた点だけ。符号そのものの位置、未知の部品名、欠けた根拠は除外する。ただし既存の引出線追跡が正しいかは別途未確認。
- 同じ投影になる近側／遠側を保存し、奥行きの非一意性を見せる。これは真の奥行きの範囲や統計的な信頼区間ではない。
- 図の誤差が小さくても実物に正しいとは限らない。`stageA3dPassed:false` と `documented3dParts:0` は常に保持する。出力名も `available` ではなく `candidates-generated`。

## Claudeへの実行指示

1. 最新のorigin/main、作業ツリー、実行環境を確認する。既知の基点に戻さず、新しい変更を保持する。添付の `codex-atlas-hypothesis.patch` をまず `git apply --check` で確認する。新規ファイルと同名の実装があれば上書きせず差分を確認する。パッチと `files/` は同じ内容で、二重適用しない。
2. 適用し、17テストを実行する。次に、前回PC752Nジョブの元の `machine.json` と `figure-p18.png` を使って、一度実行する。無ければ既存の `node scripts/atlas/run.mjs "クボタ PC752N"` で自動取得から再実行する。利用者に資料提出を求めず、取得不能ならここで未成立と報告する。対象は変更しない。
3. 同一machine.jsonで3回実行する。時刻や実行時間を含まない `experiment.json` のSHA-256を比べ、3回一致するか報告する。原本のSHA-256が前後で変わらないことも確認する。`--out` には毎回未存在のディレクトリを指定する。
4. 実ブラウザで、既存生成結果・初期仮定・調整候補・奥行き候補を切り替える。図のグループ分け、ラベル、左右・前後、形状の重なりを資料と照合する。自動検査の合格と人の目による妥当性評価を別々に報告する。
5. 共通処理の明確なバグは修正してよいが、変更理由と差分を添える。PC752N専用の座標、手入力カメラ、名称の無理な親部品への置換で成立させない。推定形状を増やして「資料照合済み5部品」と数えない。
6. この一巡で採否をまとめ、追加の機種探索・商用基盤実装・有料API契約へ広げない。実験コードの通常のmainプッシュに関する既存許可は撤回しないが、検証した変更だけを対象とし、主処理への自動接続・本番DB・実データ変更・強制プッシュは行わない。

Claudeの端末内で使うコマンド例（利用者のPCでの作業依頼ではない）:

```bash
git apply --check /path/to/codex-atlas-hypothesis.patch
git apply /path/to/codex-atlas-hypothesis.patch
node --test tests/atlas-hypothesis.test.js
node scripts/atlas/experimental/run.mjs atlas-out/ACTUAL-PC752N-JOB --out atlas-out/experiment-1
node scripts/atlas/experimental/run.mjs atlas-out/ACTUAL-PC752N-JOB --out atlas-out/experiment-2
node scripts/atlas/experimental/run.mjs atlas-out/ACTUAL-PC752N-JOB --out atlas-out/experiment-3
sha256sum atlas-out/experiment-{1,2,3}/experiment.json
node scripts/atlas/experimental/check-browser.cjs atlas-out/experiment-1
```

実際に存在するジョブパスへ置き換える。追加・修正ファイルをコミットする場合は、既存の `npm test` / `npm run build` も実行して結果を分けて記載する。原本・出力データ一式を無条件でリポジトリへ追加しない。

## 今回の評価と終了条件

| 判定対象 | 成功の意味 | 失敗時 |
| --- | --- | --- |
| 接続の実現性 | 未登録実機の自動ジョブを無編集で読み、資料の座標が3D候補の配置計算へ入る | 使えなかった名前・根拠・グループをそのまま報告 |
| 再現性 | 同一入力3回のexperiment.jsonが一致し、元データを変えない | 差が出たキーと原因を報告 |
| 有用性の仮説 | 固定配置より説明に使える候補か、実資料の図と実ブラウザで評価できる | カメラ、分割、中心仮定、形状、衝突のどれが原因か切り分ける |
| 元の工程A | 資料による主要5部品の3D対応と実物一致の根拠が必要。今回の機械的テストでは合格にしない | 3D照合済み0のまま。次に必要な証拠を1つに絞る |

訓練に使った点への誤差と、1点を外して予測した誤差を必ず併記する。後者も実3D精度の証明にはならない。「5つ表示されたから達成」「見た目が似たから検証済み」という判定は禁止。

## 報告はこの形で一度に返す

1. **採用／条件付き採用／棄却**と、その理由を3行。これは本案の採否であり工程Aの合否とは別。
2. mainと実行SHA、実機の型式、入力ファイルSHA、実行回数、各回時間、外部API回数、機種固有の人手介入回数。共通の形状仮定を人が設計した事実も明記する。
3. 部品表：名前・図の符号・根拠の種類・割り当てた形状・所属する図グループ・投影誤差・予測誤差・除外理由。資料照合済み3Dと形状仮定は別列。
4. **実現性**：自動で動いた箇所、動かなかった箇所。**再現性**：3回のSHA。**課題**：観測した失敗。**仮説**：次に試す変更を1つだけ。
5. `experiment.json`、`run.json`、`viewer.html`、比較画像、Claude側の修正diffを添付。Artifact URLだけにしない。ユーザーに環境調査やPC作業を戻さない。

## Codexが確認した範囲

- 合成データの17テスト: 合格。投影への接続、再現性、奥行きの非一意性、異常値、誤った名称対応の拒否を確認。
- 合成データ10部品でCLIが最後まで実行でき、JSONと外部CDN不要のHTMLを生成。HTML内の通常スクリプトとモジュールの構文確認は合格。
- 実ブラウザ確認は未実施。PlaywrightはあるがChromium実行ファイルがこの環境になく、起動時点で停止した。描画成功・iPhone成功とは主張しない。確認スクリプトを添付した。
- PC752Nの実データはこの作業環境にないため未実行。既存103件の全回帰・Viteビルド・本番接続も今回は未実行。Codeレビュー、合成テスト、実機への適用を混同しない。
