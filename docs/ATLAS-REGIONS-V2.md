# Codex修正案 v2: 形状の絞り込み前にラスタ領域を分ける

作成日: 2026-09-11。確認基点: `bf521138b70daf5d34d4d41c42d53593edcb708c`。
Codexがコードを書く。Claude Codeが実データで実行し、実現性・再現性・課題・仮説を報告する。
今回も元の工程Aの基準、最低5点、形状仮定14種は変更しない。

## 今回直す欠陥

私のv1は、形状仮定に一致する7点まで減らしてから「8点以上で分割」という処理へ渡した。そのため分割が作動せず、2つの機械図を1カメラに混ぜた。実データ報告のLOO 1398.7px / 37.4%は、その条件下の予測誤差である。3D精度そのものの測定ではなく、分割修正後の予測力もまだ確認できない。

最新コードを確認すると、`pdffigure.mjs`にはラスタ抽出と引出線追跡はあるが、機械図ごとの連結成分・領域IDの計算はない。「計算済みの領域を使うだけ」という報告の前提は、当該mainでは確認できない。今回、その処理を実験用に追加した。

またv1は誤差を出力するが、誤差で候補を自動棄却する判定はない。大きなLOOでも`candidates-generated` / exit 0になり得た。「自動で不合格を出した」は正確ではなく、数値と画像を見てClaudeが棄却した。v2でも新しい誤差閾値は導入しない。今回の自動停止は**所属が未確定／領域内が5点未満**である。

## 変更内容

1. 既存ジョブの原PNGを読み、SHA-256と原寸を照合。8bitのグレー/RGB・非インターレースだけを扱う。これは現行`pdffigure`の出力形式。画像不在、破損、形式不一致では所属不明として止める。新しい外部依存は追加しない。
2. 画像全体を長辺最大640セルへ縮小し、インクを含むセルを連結成分に分ける。半径1セルと2セルで接続を比較し、拡張すると別の大きな領域と合流する成分は保留。細い線による連結や余白にある点を、近い機械へ無理に振り分けない。
3. **形状に一致するかを問わず、全25点へ所属を付与**。元JSONを変更せず、メモリ上の複製の`positionEvidence.viewRegion`へ記録する。出力の`regions.json`に全点・領域枠・理由を保存する。点数や機種ごとに閾値を変更しない。
4. その後で既存の形状・引出線条件を適用し、元画像の識別情報＋領域IDでカメラを分ける。所属不明の点をページ全体に戻さない。4点と3点なら別々に`insufficient-anchors`で停止する。
5. 分割しない計算は`mixed-view-negative-control`として数値比較だけ残す。候補の配置には使わず、`updates`も出力しない。未計算の形状を投影に基づく配置と表示しない。
6. 停止時のビューアでは初期仮定だけを表示し、調整後・近側・遠側を無効化。カメラがなくても資料の点を描画できるようにした。停止を失敗と誤認しないようブラウザ確認スクリプトも対応。ClaudeのPlaywright/Chromiumパス対応は保持する。

### 出力

- `experiment.json`: 領域ごとの点数・カメラ計算の可否・対照実験・3D照合0。
- `regions.json`: 元の全点の領域所属、領域枠、保留理由、使用パラメータ。
- `regions-1.svg` 等: 原画像に全点と領域枠を重ねる。未知の形状・符号位置のみの点も含む。自己完結ファイル。
- `viewer.html`: 比較画面。停止時は初期の仮定だけ。通常スクリプトと3Dを分離。
- `run.json`: 時間、API回数、入力SHA、停止理由等。

`figureKey`は画像用のキーとして維持する。領域IDを単純に追加すると旧ビューアの寸法解析が壊れるため、カメラのグループキーは別にする。

## この方式の限界

連結したインク領域は、カメラの視点そのものではない。前面図・背面図の名称も自動では確定しない。機械図が途切れる、引出線が別図へ触れる、差込図や文章が大きな成分になる等の失敗はあり得る。安定性判定も視点の正しさの証明ではない。

今回の保守的な処理では、大きな領域が1つしか検出できない画像を自動で「単一視点」と認めず、`single-or-no-region-unverified`として保留する。正しい1枚図でも止まり得る。これは実験用の制約として明示し、本体パイプラインには適用しない。

従って「異なる**領域ID**をカメラへ混ぜない」はテストで確認できるが、「実物の異なる**視点**を完全に識別できる」は未確認。PC752Nの原画像と重ね図で評価する必要がある。図が分かれても4点・3点なら3D生成は未成立のまま。形状仮定の拡充や最低点数の引き下げで、今回の分割結果をごまかさない。

- 同じ合成入力でCLIを3回実行。3回とも終了コード1（意図した停止）、`experiment.json` SHAが一致、原JSONは不変。10点を5点・5点に分ける対照テストでは独立した候補計算が可能。

- **未確認**: PC752Nの実画像、実ブラウザのv2、iPhone、既存120件を含む全回帰・Viteビルド。本環境ではChromium実行ファイルがなく、実ジョブ添付の実体も確認できない。前回のClaude実測と今回のCodex合成実測を混同しない。
