# デモアカウント（運営コンテンツ）の運用

カタログが空の状態で見学者を迎えないために、運営名義のデモアカウントが
コンテンツを公開している。公開するのは**農業機械の整備ガイドのみ**で、
メーカーごとに1アカウント。守るべき原則は次の4つ。

1. 運営作成であることを明記する（作成者名・要約冒頭の注記）。
   実在の農家の実績に見せかけない。
2. **メーカー公式を装わない。** アカウント名は
   「◯◯整備ガイド（Nitoron運営・非公式）」の形式で統一し、要約冒頭に
   「◯◯株式会社とは無関係」と書く（商標・不正競争防止法対策）。
3. 他者の写真・動画・取扱説明書は転載しない（著作権法）。本文は自分の
   言葉で書き、出典欄にメーカー公式ページへのリンクだけを載せる。
4. 保安部品・排出ガス装置・フロン・出力改造には触れない。廃油等の処分は
   必ず「業者引き取り」と書く。安全と自己責任の注意書きを全記事に入れる。

## 構成

`supabase/seed/demo_account.sql` がすべてを作る。冪等なので何度実行してもよく、
文面の修正はこのファイルを直して再実行する。プロフィールページの表示名は
「そのアカウントの最新発表の `meta.author`」なので、同一アカウントの全記事で
作成者名を揃えること。

メーカーアカウント（`de300000-0000-4000-8000-0000000000xx`）:

| アカウント | ID末尾 | 公開中 |
| --- | --- | --- |
| ヤンマー整備ガイド | 11 | トラクターのオイル・フィルタ交換 |
| クボタ整備ガイド | 12 | （準備中） |
| イセキ整備ガイド | 13 | （準備中） |
| 三菱マヒンドラ農機整備ガイド | 14 | （準備中） |

その他:

- 下書き保管 `…0001`（nitoron-demo-farmer@example.com）:
  栽培記録の記入例3件と対話1組を非公開のまま保持（公開しない）
- 見学者 `…0002`（nitoron-demo-visitor@example.com）: 対話デモの相手役

メールは予約ドメイン example.com 宛のため届かず、パスワードはランダムな
ハッシュのみでログイン手段はない。操作はすべてSQL（service role）で行う。

## 撤去

実ユーザーの発表が十分に増えたら消す。ユーザー行の削除で全データが
カスケード削除される:

```sql
delete from auth.users where id in
  ('de300000-0000-4000-8000-000000000001', 'de300000-0000-4000-8000-000000000002');
```
